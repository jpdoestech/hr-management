# Access Control and Account Recovery Setup

## 1. Apply the database migration

1. Back up the Supabase project.
2. Confirm `supabase/phase19-tenant-scale-foundation.sql` has already been applied.
3. Open **Supabase Dashboard > SQL Editor**.
4. Paste the complete contents of `supabase/phase20-access-control.sql`.
5. Select **Run** once.
6. Confirm the query completes without an error, then reload the application.

The migration is additive. It preserves users and HR records, marks existing Administrator profiles as superadmins, creates tenant-scoped roles and assignments, and backfills every profile into its matching system role.

## 2. Configure email redirects

1. Open **Supabase Dashboard > Authentication > URL Configuration**.
2. Set **Site URL** to the production application URL, for example `https://slsc-eis.vercel.app`.
3. Add the production URL and each approved local preview URL to **Redirect URLs**.
4. Do not use wildcard redirects for an enterprise deployment.

Password reset and email change links return to the configured application URL. The app detects a recovery session and displays the new-password form before opening the HR workspace.

## 3. Configure production email delivery

1. Open **Authentication > SMTP Settings**.
2. Configure a verified organizational SMTP sender.
3. Customize the **Reset Password** and **Change Email Address** templates.
4. Keep recovery links and confirmation tokens generated by Supabase; do not place passwords in email.
5. Test delivery, expiry, and spam placement with a non-administrator account before rollout.

Supabase development email limits are not suitable for a large user population. Use production SMTP before onboarding all employees.

## 4. Review initial access

1. Sign in as an existing Administrator.
2. Open **Documents & Governance > Access Control**.
3. Open **Roles** and review the seeded Administrator, HR Staff, Manager, Employee, and Viewer roles.
4. Open **Permission Matrix** and confirm each role has only the intended actions.
5. Open **Users**, edit each account, and verify its linked employee, manager, roles, scopes, and resource assignments.
6. Use **View Effective Access** to confirm the final result and its source.

Direct denies take priority over direct grants and role permissions. Superadmin access is an explicit bypass and should be assigned to the smallest possible number of accounts.

## 5. Configure employee password self-service

1. In **Access Control > Users**, edit an Employee account.
2. Enable or disable **Allow this employee to create or reset their own password**.
3. Save the access change.

When enabled, the employee can request a password reset email from the sign-in page or Account Security. When disabled, the application blocks both requesting and completing its password recovery flow and instructs the employee to contact the System Administrator.

Supabase's public Auth recovery endpoint exists outside database RLS. For a strict compliance environment where a technically capable user must also be prevented from calling that endpoint directly, route recovery through a server-side Edge Function and disable direct browser recovery calls. The current policy is enforced throughout this application UI and recovery flow.

## 6. Test account-owned changes

Test all of the following with Employee, Manager, HR Staff, Administrator, and superadmin accounts:

1. Select the user identity in the top bar and open **Account Security**.
2. Request a password reset and complete it from the email link.
3. Request an email change and confirm the messages sent by Supabase.
4. Verify that no administrator screen accepts or displays another user's password.
5. Disable password self-service for one Employee and confirm recovery is blocked.
6. Confirm direct denies override role permissions.
7. Confirm branch and department scopes prevent out-of-scope HR record access.
8. Confirm inactive roles no longer contribute permissions.

## 7. Operational safeguards

- Keep at least two tested superadmin accounts owned by different authorized people.
- Never share superadmin credentials.
- Review role assignments and direct grants regularly.
- Prefer reusable roles over many direct grants.
- Use direct denies for documented exceptions.
- Keep the Supabase service-role key out of this static frontend.
- Review Supabase Auth and application audit logs after access changes.
